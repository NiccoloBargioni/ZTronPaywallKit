## G2 first step: A2 · a pack credit whose write fails is finished anyway

**Root cause.** `applyPlanned` swallows a nil `appendLedger`; `handle` and `purchase` finish and report `.purchased`.

**Steps**
1. In `appendLedger`, split `journal.append` into `write` then `sync`; a failed sync after a successful write is a
   landed event (the frame is in the file), as the draw path already treats it. Only a failed `write` returns nil.
2. In `handle`, keep the planned items, apply them, refresh, then finish only if every planned id is in `ledger`
   (membership, not the append's return value: nil also means "already present").
3. In `purchase`, the same gate. When a planned credit did not land: no `finish`, no `.purchase(.completed)`, return
   `.pending` and publish `.purchase(.pending)`. The transaction stays unfinished and StoreKit redelivers it on
   `Transaction.updates` at the next launch; the deterministic `credit:<id>` keeps that idempotent.
4. Remember the undelivered pack in memory (`unfinishedPacks`) and retry it at the end of every `refresh`
   (foreground, expiry, update), finishing it once the credit lands.
5. Document `.pending`'s second meaning (`PurchaseOutcome`, README, HANDBOOK).

**Test.** `FailurePathTests`: `credit_write_failure_leaves_the_purchase_unfinished` (purchase and `handle` variants,
poison variant, sync-only variant that lands, in-session retry on `refresh`).

**Regression check.** `purchase_of_a_pack_credits_before_finish`, `credit_is_idempotent_across_relaunch_before_finish`,
`interrupted_purchase_delivers_once_on_relaunch`, every `AuditTableTests` purchase stage. An empty plan (a
subscription) still finishes as before.

## G1: wallet durability

### A6 · the change token is committed before the merged events are durable, A7 · a dropped log is never refilled

**Root cause.** The carrier owns the cursor and persists it in `pull()`, before and apart from the journal.

**Design.** The engine owns the cursor and stores it in `ledger.log`, in the same `write(2)` as the merged events.
- `LedgerSync` gains `pull(since:) -> LedgerPull?` (events, the cursor to store with them, whether the carrier has an
  account). `nil` means "did not look" (the pull interval has not elapsed): no answer, nothing settles. The old
  `pull()` stays the required primitive; `pull(since:)` defaults to it with a nil cursor, so a third-party carrier
  still compiles and pulls everything every time (correct, slower). A wrapping carrier that forwards only `pull()`
  behaves the same way.
- `JournalEntry.cursor(Data)`: written after the merged batch it covers, in one write. Compaction keeps the last one
  in place, so after any truncation the surviving cursor is older than every surviving merged event: a head drop
  leaves no cursor (full refetch), a middle drop the cursor before the corrupt frame.
- `merge` returns `Bool`; on a failed write the cursor is not written and `performSync` asks the carrier for a
  re-pull (`requestPull`) instead of settling anything.
- `PaywallCloudSync` stops owning the token: `pull(since:)` fetches from the engine's cursor; the legacy
  `cloudkit.token` file is deleted at the first pull (one full fetch, safe under the union merge).
- The device id is rotated when the load dropped a corrupt frame (not a torn tail), so events written before the
  refetch cannot fork the old stream.

**Steps**
1. `JournalEntry.cursor`, `Journal.cursor`, counting cursor frames with the markers for the compaction-at-open
   trigger, carrying the last cursor through `rewrite` in place.
2. `LedgerPull`, `LedgerSync.pull(since:)` with its default, `InMemoryCloud` serials and `InMemoryLedgerSync.pull(since:)`.
3. `PaywallCloudSync.pull(since:)`: throttle returns `nil`; `noAccount` returns an empty answer with
   `accountAvailable: false`; the legacy token file is removed.
4. `GateEngine.merge(_:cursor:) -> Bool` writing events + cursor (+ baseline settlement, see A1) in one append;
   `performSync` pulls from `journal.cursor`, commits only through a successful merge, re-requests a pull otherwise.
5. `Journal.droppedCorruptFrame`; `PaywallFiles.rotateDeviceID()` when set.
6. Tests, docs (`LedgerSync`, HANDBOOK "Retention" and "Reinstall").

**Tests.** `CloudSyncTests`: `a_failed_merge_does_not_move_the_change_token` (A6-1), the reinstall shape (A6-2),
`a_pull_that_resolves_after_shutdown_commits_nothing` (A6-3), and the A7 parameterised corruption test
(`a_dropped_log_is_refilled_from_the_carrier`: frame 0 flipped, a newer-format checkpoint, a middle frame flipped,
each with and without a truncating launch in between), asserting the events, not only the balance.
`FailurePathTests.merge_failure_keeps_the_ledger_unchanged` now also asserts the `Bool`.

**Regression check.** `two_simulators_converge_after_interleaved_draws`, `pull_interval_is_respected_until_requested`
(rewritten for the cursor API), `change_token_persists_across_launches` (now the journal's), the live CloudKit lane's
`carrier.pull()` assertions, every `InMemoryLedgerSync` test (incremental pulls return the same union).

### A1 · the Keychain baseline lasts one launch

**Root cause.** The adopted baseline lives in memory; the first write rewrites the Keychain item from the ledger.

**Design.**
- `JournalEntry.baseline(WalletSnapshot)` / `.baselineSettled`: the adopted snapshot is durable in the journal,
  loaded before the init recompute, kept through compaction, cleared by a settlement record written with the merge
  that settles it.
- Settlement: only fresh events (new to the ledger, so never this install's own echoes) for the baseline's account,
  or the baseline's named last event arriving. A nil `lastEventID` never counts as seen.
- The Keychain item keeps provenance while a baseline stands: `lastEventID` is the baseline's, the balance is
  baseline plus local events. A `{0, nil}` item is no history; a legacy `{K, B≠0, nil}` item is honoured on an empty
  ledger. Nothing is written while the engine is unbound and a baseline for another key stands, and `{0, nil}` is
  never written (it carries nothing and would clobber another key's item).
- `KeychainWalletSnapshotStore` defaults to `synchronizable: false` (a per-device item; another device's balance comes
  from CloudKit, not from iCloud Keychain, so an unanswered carrier cannot make a second device's copy permanent),
  reading the old synchronizable item once as a fallback.

**Steps**
1. Journal entries, `Journal.baseline`, rewrite carrying the current state.
2. `Ledger.balance(for:baseline:)`: nil `lastEventID` counts as unseen.
3. Engine: load the baseline at init; adopt-and-write at `start()`; settle inside `merge`; `persistSnapshot`
   provenance rule and write guards; `bind` persists.
4. Keychain default and fallback read.
5. Tests, docs (HANDBOOK "Reinstall", README reinstall row).

**Test.** `CloudSyncTests.a_reinstall_with_icloud_off_keeps_its_balance_across_launches` (two relaunches at 120, a draw
then two relaunches at 119 with `canPass`, a second reinstall, the offline variant, the iCloud-on upload variant with
exactly one `grant:welcome`, and a purchase after the reinstall staying at 130), plus relaunches added to
`GateEngineTests.reinstall_keeps_the_balance_through_the_keychain_snapshot` and
`WelcomeTokensTests.a_reinstall_with_a_keychain_snapshot_is_not_a_new_account`.

**Regression check.** `ReviewFixTests` baseline tests (an un-uploaded draw still steps aside when the carrier delivers
the account's history; an empty carrier leaves the snapshot standing; another device's snapshot is not adopted over
history), `RetentionTests.a_corrupt_checkpoint_is_recovered_from_the_snapshot_and_the_carrier`, the live CloudKit
reinstall test.

### A9 · with no iCloud account the covered outbox grows in `ledger.log`

**Design.** Compaction moves the covered, unacknowledged events to `outbox.log`, a second framed file the open never
decodes; `pendingUpload` reads it only when a push runs; acknowledgements prune it; a head drop of `ledger.log` drops
it too (consistent with A7: unuploaded events of a lost log are counted by the Keychain baseline, not re-pushed on
top of it). The carrier reports `accountAvailable` on every pull and the engine stops pushing (and re-encoding the
outbox) until a pull says the account is back, pushing at once when it is. Logs in the old shape migrate at the first
`start()`.

**Steps**
1. `Journal.outboxURL`, framed append/prune/read, `pendingUpload` union, `coveredOutboxInLog` for migration,
   deletion on a head drop.
2. `rewrite`: write the outbox file (synced) before the rename; drop covered unacknowledged events from the log when
   an outbox is kept.
3. Engine: `carrierHasAccount`, the push gate, the regained-account push; `acknowledge(ids)` writing markers for log
   events and pruning the file for the rest; migration in `writeCheckpointIfDue`.
4. Tests, docs (HANDBOOK "Retention", README Known defects: the outbox still grows on disk while the user never signs in).

**Test.** `CloudSyncTests.a_device_without_an_icloud_account_still_bounds_its_journal` (301 events, threshold 50,
checkpoint + at most 50 entries decoded, 700 balance, sign in → 301 in the cloud, outbox empty, reinstall from the
cloud at 700), a migration test over a log in the old shape, and a crash between the outbox write and the rename.

**Regression check.** `RetentionTests.a_checkpoint_keeps_the_outbox_until_the_carrier_acknowledges_it` (entry
counts move to the outbox file), `JournalTests` checkpoint tests, `outbox_ack_lost_does_not_double_upload`.

## G2 rest: lifecycle discipline

### A5 · a shut-down engine keeps writing

**Steps**
1. `Journal.close()`: `fd = -1`, `isClosed`; writes and `rewrite` refuse afterwards. `shutdown()` closes it and clears
   the sessions.
2. Guards after every await in `start`, `refresh`, `handle`, `purchase`, `restore`; `appendLedger`, `emit`, `decide`
   and the listener starts refuse after shutdown; `requestPull` is skipped.
3. A purchase that completes after shutdown is handed to `onOrphanedPurchase` (the facade forwards it to the current
   engine's new `adoptPurchase(_:source:)`, which credits, finishes and publishes it); the dead engine returns
   `.purchased` when the successor finished it, `.pending` otherwise.
4. The facade starts the successor only after the predecessor's audit trail flushed, so the audit chain stays linear.
5. Rewrite `ReviewFixTests.a_shut_down_engine_starts_no_more_background_work`.

**Test.** `ServiceProviderTests.a_purchase_that_completes_after_a_reconfigure_is_credited_by_the_successor` (4096
chained grants so the successor checkpoints, a held payment sheet, a reconfigure on the same directory, release:
the live wallet and the next launch show 4105 and both chains verify), its 5-event twin, and the cancelled-sheet
twin; `RetentionTests.no_checkpoint_is_written_once_the_engine_is_shut_down` extended (no listeners, empty journal,
no entitlement.json).

### A4 · overlapping refreshes apply in finish order

**Steps**
1. `resolutionGeneration` bumped at the top of `refresh`; `lastAppliedGeneration` compared right before the
   synchronous apply block; a stale resolution skips it (its revocation scan may still run).
2. A stale resolution that bound a different app transaction schedules one more refresh.

**Test.** `ResolutionOrderingTests` (new suite) with a `LatchedStore`: the purchase case, the refund mirror, the hold
on `start()`'s launch resolution. All three fail at `b5c20e4`.

### A8 · reconfiguring orphans the gated views on screen

**Steps**
1. The facade tracks live view sessions (`openSession`/`closeSession`, every branch).
2. After `configure` (after `start()` for an engine, at once for passthrough and failure branches) every live session is
   reopened on the new engine and its first state delivered through `onChange`; a view that was open through a lease
   is re-pinned first so it never draws twice.
3. `teardown` leaves the dead engine's sessions to `shutdown()`, which drops them silently.

**Tests.** `PassthroughTests.flipping_passthrough_off_re_evaluates_gated_views_on_screen` (and the welcomeTokens-1
variant with exactly one `tokensConsumed`), `flipping_passthrough_on_opens_denied_views`;
`ServiceProviderTests`: a denied `.paid` view opens after `use(.fake lifetime)`, after `useProduction` plus a purchase,
and a drawn `.deductNow` view survives a same-journal `useProduction` past `tolerance` with no second debit.

### A12 · every launch decodes the whole audit log

**Steps**
1. `repairAudit` reads `retainedSince` and `lastRecordHash` first, computes the candidates, resumes the trail, and
   skips the lookup when nothing is left.
2. `PaywallAuditRepairing.recordedDebitIDs(among:)` with the intersecting default; `JournalSink` scans newest file
   first, decodes only lines containing `"debitID"`, stops once every candidate is found.
3. `RetentionTests`' `ShuttingDownSink` moves its shutdown into `lastRecordHash()`.

**Tests.** `RetentionTests.a_launch_with_no_debit_to_check_does_not_scan_the_audit` (counting sink, both counts 0,
chain intact; repeated with every debit below the floor) and `the_candidate_lookup_matches_a_full_decode`.

## G3: entitlement resolution

### A3 · billing grace resolves `.free`

**Design (Option A).** `StoreClient.renewalGraceEnd(groupID:)` (default nil; `StoreKit2Client` reads
`RenewalInfo.gracePeriodExpirationDate` of a `.inGracePeriod` status) is read by `refresh` only when a listed
auto-renewable of the catalog has lapsed and nothing else pays. The resolver keeps that row while `graceEnd > now`
with `phase: .inGracePeriod`, `Subscription.gracePeriodEndsAt` and `resolution.expiresAt = graceEnd`; the launch
snapshot judges `gracePeriodEndsAt ?? expiresAt`. Offline the read fails and the lapsed row resolves `.free`, as today.

**Tests.** `ResolverTests.a_subscription_in_billing_grace_stays_subscribed_until_grace_ends`; `GateEngineTests`
grace test (paid gate stays open, no `.free` via `.expiryTimer`, exactly one sleeper, flips after the grace end);
`FailurePathTests` snapshot inside grace; `SimulatorTests.renewal_expiry_grace_and_billing_retry` asserts the listed
row has lapsed.

### A10 · paid introductory offers resolve as a free trial

**Steps.** `StoreKit2Client.isIntroductoryFreeTrial(offerType:paymentModeRawValue:)`, a pure static; the typed
`Transaction.Offer` path on iOS 17.2+; `StoreTransaction.isIntroductoryOffer` means "introductory free trial" (doc).
A pay-up-front introductory offer on `pro.yearly` in `Paywall.storekit`, and a host-lane test that buys it and expects
`tier == .yearly && !isTrial`.

### B14 · the fake's "store down" is a thrown read StoreKit never produces

**Steps.** `FakeStore.setReachable(false)` now holds passive reads (they never answer, `pendingReads` counts them) and
fails the network calls; `setPassiveReadFailure(_:)` is the named throwing-client mode, documented as not StoreKit
behaviour; `.storeUnavailable` and `PaywallPreset.storeDown` docs say what production does. The simulator's `storeDown`
is built on the no-answer mode: `start()` waits, gates fail closed, nothing is published.

**Tests.** `TestDoubleTests.fake_store_passive_reads_answer_like_storekit_when_offline`; `EdgeCaseTests` hold cases
(a) and (b) with no `.storeUnavailable`; the simulator guard stays.

## G4: grandfathering trust

### A11+B6 · the receipt is never bound to the device

**Steps.** `ReceiptClient.snapshot()` (now async) checks field 5 = SHA-1(identifierForVendor bytes ‖ field 4 ‖ field
2) when the client has an identifier (`deviceIdentifier: @Sendable () async -> UUID?`, `UIDevice` on iOS, nil elsewhere
and before first unlock → nil snapshot, cache kept); fixtures gain fields 4 and 5 for a fixed fixture identifier plus
`receipt-other-device.der` and `receipt-no-device-hash.der`; `StoreKit2Client` falls back to the receipt only when
`AppTransaction.shared` throws, never on `.unverified` (pure decision `usesReceipt(after:)`); docs corrected.

**Tests.** `ReceiptClientTests`: every layout verifies with the fixture identifier; a random UUID, the other-device
receipt, the no-hash receipt and a nil identifier each give nil; `ProductionReceiptTests` refuses the copied receipt
with a random identifier; the engine test seeds a receipt-origin cache from the other-device receipt and relaunches.

### B1 · the caches on disk are trusted

**Design.** `PaywallFileKeyStore` (32 random bytes that never leave the install; `KeychainFileKeyStore` in PaywallKit,
`InMemoryFileKeyStore` in PaywallTesting). `PaywallFiles` writes `app-transaction.json` and `entitlement.json` as an
envelope `{payload, mac}` with HMAC-SHA256 (pure Swift in Core) and drops a file whose tag fails or is missing (a
legacy file is never laundered). `account.key` goes: the key is derived from the authenticated snapshot. A missing key
(Keychain before first unlock) writes and trusts nothing. The grandfather token grant is minted only when the store
answered in that refresh. Without a key store (`GateEngine` used directly) the files are plain, as before: documented.

**Tests.** `GateEngineTests.forged_app_transaction_cache_grants_nothing_offline` (lifetime and tokens), the forged
`entitlement.json` is `.unknown`, a transient key-store failure keeps the key, a legacy file is dropped and never
MAC'd; `grandfather_survives_offline_launch` and `a_lapsed_subscription_snapshot_launches_as_free` stay green.

### B9 · unbounded DER recursion

**Steps.** `parseNode` takes a depth, refuses past 64; nodes hold slices into the input instead of copies
(`AppleReceiptVerifier.signedMessage` and `SignedReceipt.certificates` copy where they mutate or keep). Tests: open,
indefinite and definite nests at 100 000 / 20 000 levels return nil, fail `isAuthentic`, throw `.malformed` and give a
nil snapshot from a `@concurrent` helper; the boundary at 64 parses and 65 does not; every fixture stays green.

### B2 · VPP receipt types

**Steps.** `ProductionVPP` → `.production`, `ProductionVPPSandbox` → `.sandbox`, exact matches; an empty field 19 is
missing (nil); field 21 (the VPP expiration) is read and `snapshot(now:)` fails closed once it has passed; README
limitation and HANDBOOK mapping. Tests: the parameterised type table, `vpp_receipt_without_purchase_history_fails_closed`,
`empty_original_version_is_never_admitted`, the field-21 pair.

### B13 · the account-key parity check is a tautology (test-only)

**Steps.** `the_same_installs_app_transaction_derives_the_receipts_account_key`, gated on
`PAYWALL_PRODUCTION_RECEIPT` and `PAYWALL_PRODUCTION_APP_TRANSACTION`; `ResolverTests.account_key_matches_across_sources`
